# ADR-027

标题：V1 用户旅程以今日开单本为主界面；嘴巴只写当前单；确认=生意事实成立

- 状态：proposed
- 日期：2026-08-17

## 背景

[V1_SALES_CLERK.md](../V1_SALES_CLERK.md) 已定义开单员岗位与一天六步。产品化若没有用户旅程，容易把工作台做成 ERP 列表，或让语音按客户名在多张单之间自动跳转。

用户旅程：[V1_SALES_CLERK_USER_JOURNEY.md](../V1_SALES_CLERK_USER_JOURNEY.md)。服从 [RUNTIME_FREEZE.md](../RUNTIME_FREEZE.md)。

## 问题

老板一天里，眼睛看哪一页、嘴巴写哪一张、说「好了」到底定的是什么？

## 决策

1. **主界面 = 今日开单本**（数量 / 待确认 / 已确认 / 入账状态 / 异常）。不是 ERP、不是聊天。
2. **嘴巴只对着当前这一张。** 换客必须显式开下一单或点待确认变成当前。禁止按客户名自动跳单。
3. **确认 = 老板承认这笔生意事实成立并留底。** 不是付款完成、不是发货完成、不是财务完成。
4. 已确认单不能喊着改。价未定可确认。入账只给眼睛看。
5. 不新增 Agent，不改 Runtime Freeze，不引入收款 / 库存 / 财务。

## 原因

档口乱在换客快。智能路由会把李老板写进张老板页。本子给人看、笔按在一页上，才是伙计坐得住的原因。

## 影响

- 好处：连续接单不串页；「好了」不会被理解成已收款。
- 限制：不能喊着改已确认单；不能用嘴查跨单；收摊不对钱。
