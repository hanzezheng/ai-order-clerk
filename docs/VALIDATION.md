# 行为迁移实验（Sprint 6A.6）

> 验证的不是「还缺什么功能」，而是：**档口老板体验过 AI 开单之后，会不会改习惯。**
>
> 本文件是实验方案、观察记录模板、Demo 剧本，以及进入 Sprint 6B（真 ASR/TTS）的行为门槛。
>
> 冻结：不改 Parser / Resolver / Policy / Memory / OrderService / Response；不做 ASR、TTS、ERP、登录。剧本必须能在**当前 Demo** 上跑通。

当前 Demo 仍是文本模拟语音。实验照此进行。若用户第一反应是「这不是说话」，记为观察，不要当场改成功能清单。

---

## 0. 实验在验证什么

| 要验证 | 不要验证 |
| --- | --- |
| 第一次：没有人教，能不能开完一单 | 还想要哪些按钮 |
| 第三次：会不会开始用自己的话 | 界面好不好看 |
| 第十次：明天不能用会不会觉得麻烦 | 喜欢打几分 |
| 卡在「想说话却只能打字」还是「不知道这是什么」 | ASR 准不准（现在没有麦） |

三次观察点：

1. **第 1 次**：能否完成。
2. **第 3 次**：是否自然表达。
3. **第 10 次**：是否形成依赖。

样本：农批档口老板或每天代开单的熟手，**5–8 人**即可。不是问卷，是旁观。每人至少 1 次；能约到的做满 3 次；第 10 次用回访，不必全员到齐。

主持人：在场，但**第一次不讲解产品**。只说「用这个开一张单」。用户问「怎么用」时，先等 10 秒；仍不会，记一次「需要人工解释」，再给最短提示：「按住说话，或点例子。」

## 1. 第一次接触流程

场景：用户没培训。屏幕上只有 AI开单员页面（不要 `?dev=1`，不要打开时间线）。

### 流程

1. 打开 `http://127.0.0.1:8000/`（或环境转发的 Demo 端口）。
2. 把设备交给用户。主持人退到能看见屏幕、不插手的位置。
3. 任务口述（只这一句）：**「用它给李老板开一张单。」**
4. 不补充「要按住说话」「可以点下面的例子」「没有麦克风」。
5. 计时：从页面可见到草稿状态变为已确认（或用户放弃）。
6. 完成后不要立刻问「喜不喜欢」。按 §3 记可观察行为，再问 §3.5 的替代意愿。

### 观察（第一次）

1. **是否知道如何开始**（10 秒内是否摸到「按住说话」或点了「开李老板的单」）。
2. **是否理解可以直接说话**（对着屏幕说 vs 找键盘 vs 找表单）。当前是文本模拟，用户对着空气说话也算「理解语音产品」；去找加行表单算「当成 ERP」。
3. **是否需要人工解释**（10 秒后仍停住，或明确问「怎么弄」）。

通过线（第一次）：无人讲解下开完一单，或只在提示「按住说话，或点例子」之后开完。  
失败但仍有迁移信号：完成不了，但主动说「要是能直接喊就好了」。这不是 6B 的通行证，而是 Demo 壳的问题清单。

## 2. 30 秒体验任务

固定任务，四件事都要发生：**客户、多商品、修改、确认**。并露出内核已有的四件事：连续表达、理解、业务记忆、价格谨慎。

### 标准任务（当前 Demo 可跑）

给用户的话（第一次尽量只给目标，不给逐句台词）：

> 给李老板开单：苹果 60 件，梨 60 件，梨改成 80 件，好了。

系统里李老板有档案：苹果默认红富士。价可以未定。不要让用户报价，以便观察「价未定」是否被接受。

期望事实（看草稿和 `reply_text`，不看用户是否喜欢）：

| 要点 | 必须看到 |
| --- | --- |
| 客户 | 绑到李记果行 / 李老板 |
| 多商品 | 苹果行 + 梨行 |
| 修改 | 梨数量为 80 |
| 记忆 | 回复里有「红富士」或「按档案」（用户只说了苹果） |
| 价格谨慎 | 回复里有「价未定」；没有编造的单价 |
| 确认 | 草稿已确认 |

### 推荐口令（熟悉用户 / 展示用，内核已支持）

新用户若自己说，不纠正用词。下面仅当用户卡住或展示需要时使用：

1. `开李老板的单`
2. `苹果60件梨60件`
3. `不对梨改80件`
4. `好了`

或一句连报（展示连续表达）：

`开李老板的单苹果60件梨60件不对梨改80件好了`

（若规则 Parser 对超长连报不稳，展示版拆成两句：先开单，再 `苹果60件梨60件不对梨改80件`，最后 `好了`。）

禁止当场加：库存、收款、登录、真麦克风。任务失败就记卡点，不改内核。

## 3. 行为指标

不评「喜欢吗」。只记能看见或能数的东西。

### 3.1 首次成功时间

打开页面 → 第一单确认。放弃记为失败，并记下停在哪一步。

| 档 | 含义 |
| --- | --- |
| ≤30 秒 | 30 秒体验成立 |
| ≤2 分钟 | 能完成，习惯未形成 |
| \>2 分钟或放弃 | 第一次路径不成立 |

### 3.2 主动操作次数

从开始到确认，数点击 / 点芯片 / 按回车。对着空气说话也算一次「表达」，但当前 Demo 若必须打字，把「击键提交次数」和「点芯片次数」分开记。

迁移方向：第 3 次应少于第 1 次，且更少点芯片、更多自己的话。

### 3.3 询问次数

AI 打断：`reply_mode=ask` 或用户被问「哪一家 / 哪一种」的次数。  
本任务选李老板，**不应**因同名客户被打断。若被问价、问规格，记为价格/层级不谨慎或记忆未生效。

用户问主持人的次数单独记（那是人工解释，不是 AI 询问）。

### 3.4 表达变化

| 次数 | 看什么 |
| --- | --- |
| 第 1 次 | 是否照着芯片 / 提示说「开李老板的单」 |
| 第 3 次 | 是否开始用自己的话（「李老板，来六十件苹果，梨改八十」）且不再盯着示例 |
| 第 10 次 | 是否不看页面也能开；是否主动打开这个工具而不是本子 |

判定「自然表达」：本轮至少有一句**不是**三枚示例的原文。

### 3.5 替代意愿（第 1、3、10 次各问一句）

不问喜不喜欢。问：

> 明天如果这个用不了，你开这张单会不会觉得更麻烦？

只记：会 / 不会 / 说不清。  
「会」= 开始依赖。「不会」= 还没替代本子或旧软件。

### 3.6 进入 6B 用的汇总（不要提前算成功率当 KPI 游戏）

每人每次填一张 §4 表格。阶段结束看：

- 第 1 次无人讲解完成率
- 第 1 次「需要人工解释」率
- 第 3 次自然表达率
- 第 3 次或第 10 次替代意愿「会」的人数
- 主卡点是「想说话」还是「不知道怎么开始」还是「不信价未定」

## 5. Demo 剧本

三个版本共用同一内核，不改产品。差别只在**主持人说多少话**和**用户第几次来**。

### 5.1 新用户版 — 第一次理解产品

目标：没人教，能不能明白这是开单员，并开完一单。

主持人只说：「用它给李老板开一张单。」  
不演示点哪里。芯片在，但不提醒。

成功：30–120 秒内确认；用户看见货和「价未定」。  
失败常见型：找表单、不敢点、把芯片当广告、对着空气说话却没提交。

### 5.2 熟悉用户版 — 验证习惯形成

同一人第 3 次（或当天连开三单的第 3 单）。

主持人只说：「还是李老板，你自己开。」  
不要把标准口令念出来。

看：是否还点三枚示例；是否自己连报；改口是否还找删除键；替代意愿是否从「说不清」变成「会」。

加一条（仍不培训）：若第 1 次只开了苹果，第 3 次要求带改口，用 §2 标准任务。

### 5.3 行业展示版 — 给合作伙伴看

目标：让对方看见「员工」而不是语音输入框。主持人可以演示，但口播仍只信屏幕上的 `reply_text`。

建议 40 秒内说完（可对着屏幕打字模拟）：

1. `开李老板的单`
2. `苹果60件梨60件不对梨改80件`
3. `好了`

停住，让对方读回复：档案（红富士/按档案）、改口、价未定、单已确认。  
不要打开 `?dev=1`。不要讲架构。若被问「两个王老板怎么办」，另开一单说 `开王老板的单`，展示必须问哪一家——这是附加段，不计入 30 秒主任务。

## 6. 何时进入真 ASR/TTS（顺延，不是本仓库的 Sprint 6B）

产品 Sprint 6B 已改为 **Learning Memory Loop**（确认事件学习）。真麦克风 / TTS **另批**。技术已经接得上 turns，所以技术完成不能当绿灯。

### 可以进入真 ASR/TTS

同时满足：

1. **第一次能完成**：至少半数被试在无培训下开完第一单（允许一句「按住说话，或点例子」）。
2. **第三次开始像在说话**：至少半数在第 3 次出现自然表达（非芯片原文）。
3. **卡点是声音而不是理解**：完成者里，主抱怨是「我想喊、不想打字」，而不是「不知道这是干什么的」。
4. **有替代萌芽**：第 3 次或第 10 次，至少有人明确说「明天不能用更麻烦」。

### 不要进入真 ASR/TTS

出现任一条就先留在 Demo Pack / 体验，而不是上麦克风：

- 第一次大多需要人坐旁边教，且教完仍当表单用
- 第 3 次仍只会点三枚芯片，没有自己的话
- 替代意愿普遍是「不会更麻烦」（本子或旧软件照旧）
- 主卡点是不信「价未定」、不认档案默认、或不接受确认——这是业务信任，不是 ASR

### ASR/TTS 仍然冻结的东西

即便开 6B：不改 Parser / Policy / Memory / OrderService 来迁就演示；不上 ERP、库存、支付、登录。TTS 只念同一张嘴的 `reply_text`。
