最终目标：让一个真实老板可以从空白档口开始使用 AI 销售开单员。

空白 = **这个档口还没用过这个员工，今日开单本是空的。** 不是 Catalog 里一个人、一件货都没有。没有切片就打开页面，第一句只会问和挂起。

## 0. 结论

接入是一次 **有人盯着的试班准备**，不是上线一套客户系统。

```text
1. 过检查清单五项
2. 投影客户切片 + 商品切片（经 Read Adapter / 等价人工导入）
3. 抽查：同名会问、主货能落到 SKU
4. 第一次开门：空本 + 按住说话
5. 第一单：喊切片里已有的客和货 → 改未确认 → 好了 → 看见今日本
6. 第一周：按观察表记账
7. 决定：扩大使用 或 暂停
```

旁边要有观察人。老板只管喊。不开发导入向导，不实施全量 ERP。

## 1. 新档口接入目标

老板第一次使用前，需要准备的只有四样：

| 准备 | 谁做 | 老板需要知道 |
| --- | --- | --- |
| **今日开单本能打开** | 观察人启动页面（手机浏览器即可） | 开门看见空本，不是菜单 |
| **客户切片已投影** | 人从 ERP Customer / 现有档案抄进 Catalog | 喊得出当天熟客的名字 |
| **商品切片已投影** | 人从 ERP Item / 货盘目录抄进 Catalog | 喊得出当天主货 |
| **有人盯着** | 观察人 | 换页、同名答档口、缺数据问完再补目录 |

不需要老板：注册账号、学 ERP、先盘库存、先对欠款、先导入历史订单。

接入完成的标志（给观察人，不给老板考试）：

1. 打开 `/`，当前区写「还没有开始开单」。
2. 切片里至少有一名唯一熟客、一个可履约叶 SKU。
3. 检查清单 §1 五项为通过。
4. 观察人知道：缺客问人、缺货挂起、**不猜**。

Demo 金脚本（李老板 + 口令映射）可以给观察人热身，**不能**当成这个档口已经接入。真实第一单应关闭口令映射或只用切片里的真称呼。

## 2. 企业事实初始化

经 Read Adapter 投影进 Catalog。字段以数据边界为准，这里只列接入当天必做。

### 2.1 需要

**Customer**

| 字段 | 接入时 |
| --- | --- |
| **customer_id** | 每家一个，确认和入账都挂它 |
| **name** | 老板怎么喊 |
| **alias** | 老李、王记等 |
| **基础消歧信息** | phone **或** 档口 tags **或** 地址口述，同名组必须互不相同 |

下限：≥ 5 家，且至少 1 组同名。建议当天熟客 10–20。

**Product**

| 字段 | 接入时 |
| --- | --- |
| **item_id** | 可履约叶 SKU |
| **name** | 苹果、红富士、皇冠梨 |
| **spec** | 80 果、一级、箱装等 |
| **alias** | 八十果、金边 |

下限：≥ 5 个叶 SKU。建议当天货盘 10–30。只导入「苹果」品种、没有可确认叶，不算初始化完成。

按需：熟客「喊苹果就落到某 SKU」的人标默认。没有默认就现场问规格，不编常拿。

### 2.2 不需要

| 不导入 | 原因 |
| --- | --- |
| **库存** | 不挡确认；不是这个伙计的岗 |
| **欠款** | 财务；确认不是收款 |
| **财务** | 科目、发票、价格表写回行价 |
| 全量历史 SO、客户画像、CRM 界面 | 不是开单员认人认货 |

历史订单 0 张可以开张。Memory 仍只从之后的 `order.confirmed` 长。

初始化失败（投影读不到）：**不能猜**目录。停在询问，或推迟第一次开门，不带着空 Catalog 假装已接入。

## 3. 第一次开门流程

老板打开的是 **今日开单本**，不是 ERP、不是聊天。

### 3.1 看到什么

```text
今日开单                          今天 0 张
────────────────────────────────
○  当前    还没有开始开单
────────────────────────────────
   （待确认 / 已确认 皆空）

         [ 按住说话 ]
```

没有收款、库存、报表。空本是正常开张。

口播还没有句子。当前区最大，写着还没有开始开单。

### 3.2 如何开始第一单

1. 客人来了（或观察人请老板用熟客演一单）。
2. 老板 **按住说话**（文本等价）：喊切片里已有的客和货。  
   例：「开李老板的单，苹果二十箱。」
3. 当前区出现待确认草稿：客户、货、数量。口播复述这一张。复述 **不是** 确认。
4. 要改量：未确认前继续喊「刚才苹果改 30 箱」。
5. 点头了说 **「好了」**。本子这张变已确认；入账旁可见排队中 / 已进草稿 / 看不见。
6. 下一客：必须 **再开一单**，不能把货写进已确认页。

观察人第一单只做三件事：提醒按住喊、缺数据让系统问、好了之后让老板看一眼今日本。不代老板填表。

第一单失败（认错人、货挂起）：按 §4 问和补目录，**不要**为了交差改 Confirm Gate 或自动建档。

## 4. 数据缺失处理

老板说：

> 张老板苹果 20 箱

目录里 **没有张老板**，也 **没有可确认的苹果 SKU**（只有类目、或完全没有苹果）。

系统不得编一个张老板、不得新建苹果 SKU、不得拿李老板顶上。

```text
Input
  ↓
Resolver 查投影
  ↓
没有张老板  → 询问：「还没有这位，是哪家档口 / 电话？」
没有苹果SKU → 挂起这一行：问规格或货名，行未到 sku 不能「好了」
  ↓
等待补充
  观察人把企业事实补进来源（档案/ERP）
  → Read Adapter 再投影
  → 老板再喊同一句
```

| 缺什么 | 系统 | 人 | 等什么 |
| --- | --- | --- | --- |
| 没有张老板 | **询问**，不建客户 | 记下称呼与档口 | 投影里出现 `customer_id` |
| 没有苹果 SKU | **挂起**，不创建 SKU | 记下货名规格 | 投影里出现叶 `item_id` |
| 有苹果品种无规格/默认 | **询问**规格 | 可补默认或当场说 80 果 | 行到 sku 才能好了 |
| 两个张老板 | **询问**哪一家 | 答档口 | 唯一 `customer_id` |

等待补充期间：当前单可以停在待确认/buffer，**禁止**用猜的客或货点好了。补的是企业事实，不是 Prompt，不是新 Agent。

失败案例按观察表单记：老板说什么、AI 理解什么、正确结果、主因 **数据不足**。原话不进 Memory。

## 5. Pilot 第一周观察

建议至少 **3 个早市**，含 1 次高峰。每天一张观察表，旁边有人记。老板不填表。

第一周必记：

| 项 | 记法 |
| --- | --- |
| **每天订单数** | 今日本上有内容的单（待确认 + 已确认） |
| **AI 参与订单比例** | 走到「好了」的单 ÷ 当天全部开的单（含仍手写/微信的） |
| **人工纠正次数** | 观察人提醒换页、代点、解释状态、改口令；外加老板因 AI 听错而重喊 |
| **失败案例** | 每一笔单独一条（输入 / 理解 / 正确结果 / 主因） |

其余效率、信任、错误四类仍用 [V1_SALES_CLERK_PILOT_OBSERVATION.md](V1_SALES_CLERK_PILOT_OBSERVATION.md)。

第一周看趋势，不看功能数量：

- 比例上升、回退手写下降 → 接入有效。
- 订单不少但比例接近 0 → 页面在，伙计没雇上。
- 失败几乎都是数据不足、且当天能补上再开 → 正常接入。
- 失败是串单、状态不清、或为了顺滑在猜 → 不要扩大。

## 6. 上线退出条件

第一周结束只选一条。不是再加功能。

### 继续扩大使用

同时满足：

1. 检查清单五项仍通过。
2. 多数天：AI 参与比例明显大于 0，成功开单多于失败。
3. 老板愿意喊下一单，收摊看今日本；回退手写为否或仅偶发。
4. 失败以数据不足为主，且靠 **询问 → 人补投影** 闭环，没有靠猜。
5. 老板原话接近「少记单」，不是「功能很多」。

扩大 = 同一档口更多熟客进切片、观察人少插手换页、可选关 Demo 映射。仍有监督。仍不加收款库存。对应观察表的 **继续 V1.1**（冻结外侧）。

### 暂停

出现任一条：

1. 切片没准备好就开张，第一句全靠猜或观察人代填。
2. 老板回退手写 / 只翻聊天；AI 参与比例连续接近 0。
3. 串单、状态不清、确认后还想改，反复发生。
4. 为了现场顺滑：自动建客户、自动建 SKU、让 ERP/库存挡「好了」。
5. 想顺便上 CRM、实施全量 ERP、加第二员工。

暂停 = 停扩大、停宣传可雇。回去：补切片、改旅程/工作台话术，或按观察表 **调整产品流程**。不改 Confirm Gate。

## 7. 从空白档口到第一单（收口）

```text
空白档口（没用过这个员工）
  → 检查清单通过
  → 投影客户切片 + 商品切片（不要库存/欠款/财务）
  → 开门：空的今日开单本 + 按住说话
  → 第一单：喊已有客和货 → 改未确认 → 好了 → 看见本子
  → 缺张老板 / 缺苹果 SKU：询问、挂起、等人补投影
  → 第一周记账：订单数、参与比例、纠正、失败案例
  → 扩大 或 暂停
```

让一个真实老板可以从空白档口开始用：打开就看见本、喊就能写、写不准就问、问完人补事实再喊。不是从空白 Catalog 让 AI 发明客户和货。

## 评审六问

1. **哪一层？** Pilot 接入流程（人 + Catalog 投影 + 今日本）。不改内核。
2. **改 LLM 权限？** 否。
3. **改 Confirm Gate？** 否。缺 SKU 不能好了，仍是现有闸门。
4. **污染 Memory？** 否。失败原话与等待补充不进 Memory。
5. **经 Event？** 第一张「好了」才发确认事件。接入导入不经 Event 创造事实。
6. **Adapter 还是 Runtime？** 切片仍经 Adapter 投影。Runtime 只消费。不实施 ERP。
