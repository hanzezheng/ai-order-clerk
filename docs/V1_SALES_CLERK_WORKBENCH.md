本文把「今日开单本」从概念收成 **老板每天打开的那一页**：看得见、按得住、喊得动。不是再做一个内核，也不是把 ERP 搬到手机上。

---

## 0. 结论

1. **今日开单本 = 这个 AI 销售员工的工作台。** 老板开门看到的第一页，也是收摊合上的最后一页。
2. 页面只有三块：**当前这一张**、**今天其余的单**、**按住说话**。没有菜单树，没有聊天记录，没有报表。
3. 当前订单在本子上走五态：`empty → draft → pending_confirm → confirmed → posted`。这是 **给老板看的呈现**，不是新闸门。说「好了」仍然只把单定成已确认；入账是事后用眼睛看。
4. 入口是 Voice First：按住喊一句，系统写下并复述。不设计复杂聊天。
5. 原型验收：真实老板 **5 分钟内** 能开一张、改一张、定一张、看见今日本。

## 1. 产品定位

今日开单本是档口伙计手里的那本开单纸，做成一页屏幕。

它是：

- AI 销售员工 **坐在老板旁边时摊开的工作台**
- 嘴巴正在写的那一页 + 今天已经写过的页
- 空档扫一眼、收摊对一下「开了哪些」

它不是：

| 容易做成 | 为什么不做 |
| --- | --- |
| **ERP 列表** | 一排单号、客户编码、金额、筛选器。老板高峰时不点表。入账只是每张旁边一个字，不是进 ERP。 |
| **聊天窗口** | 气泡、历史原文、滚动对讲。伙计不靠翻聊天找「刚才那箱」；当前草稿和一句口播就够。 |
| **数据报表** | 今日销售额、客单价、欠款。那是会计的桌子。开单本不合计钱。 |

一句话：这页屏幕只回答 **「现在写谁、今天开了哪些、哪张还没好了、哪张进账了没」**。

现网已有当日任务索引和入账投影。本原型只规定 **老板看见的结构与交互**，实现落在 Demo / Workbench 呈现，不改 Runtime。

## 2. 页面结构

老板每天打开看到的第一页，就是这一页。手机竖屏、档口一臂距离能看清。不进二级菜单才能开单。

```text
┌─────────────────────────────────────┐
│  今日开单              8月17日      │
│  今天 3 张 · 待确认 1 · 已确认 2    │
│  异常：入账看不见 1                 │
├─────────────────────────────────────┤
│  当前                               │
│  ● 张老板                           │
│    苹果 80果  20箱   价未定         │
│    可以好了                         │
├─────────────────────────────────────┤
│  待确认                             │
│  · （空，或昨晚没好了的单）          │
│  已确认                             │
│  ✓ 李老板  2行  价未定  入账：排队中 │
│  ✓ 王老板  1行          入账：已进草稿│
├─────────────────────────────────────┤
│         [ 按住说话 ]                │
│            好了                     │
└─────────────────────────────────────┘
```

### 2.1 今日日期

页眉左边「今日开单」，右边当天日期。本子只装 **今天**。不提供改日期、不提供历史账本入口。开门空本也显示今天的日期，空不是错误。

### 2.2 当前订单

页面最大一块。永远只有一张：正在喊的那一页。空着就写「还没有开始开单」。加亮、字大，比口播更醒目——避免连续接单写串页。

这块上只放：客户称呼、货行（品名 / 规格 / 数量）、价未定标记、本张呈现状态。不放单号、金额、库存。

### 2.3 待确认订单

写了还没「好了」的单。多数时候就是当前这一张（当前区已经展示，列表里不必重复描两遍；若当前就是唯一待确认，列表可收成一句「没有其他待确认」）。

若老板没好了就开了下一张，或昨晚留下草稿，它们出现在这里。点某一张 → 它变成当前，嘴巴对着它继续改。不靠喊客户名自动跳过来。

### 2.4 已确认订单

今天已经点头留底的单。只许看：谁、几行、价未定没有、入账字。点开也只是看，不能按住说话改它。

### 2.5 ERP 入账状态

只出现在 **已确认** 行旁边，三个字之一：

| 老板看见 | 意思 |
| --- | --- |
| 排队中 | 定了，账还在写 |
| 已进草稿 | 公司账上有这张草稿了 |
| 看不见 | 暂时对不上；不假装成功，也不撤回「好了」 |

未确认的单没有入账字。口播永不念这三个字。

### 2.6 异常提醒

页眉一条，收摊前要盯的漏，不是财务红灯。

| 提醒 | 老板做什么 |
| --- | --- |
| 还没好了 N | 点回来继续喊，或自己决定不要了 |
| 客户还没认清 N | 回答是哪家档口 |
| 入账看不见 N | 知道这张留底可能还没进账，继续开下一张没关系 |

价未定是行上的黄字标签，**不算异常**。

### 2.7 这一页明确没有

收款、库存、筛选、加行表单、聊天记录、ERP 单号、开发时间线（仅 `?dev=1`）。主操作只有 **按住说话** 和 **好了**；换页只有 **下一单** 和点待确认。

## 3. 当前订单交互

当前这一张在本子上的呈现，按下面走。箭头是老板能感觉到的顺序，**不是新的 Confirm Gate**。

```text
empty
  → draft
  → pending_confirm
  → confirmed
  → posted
```

闸门仍然只在「好了」：人没认清或一行货都没有，不能确认。缺价不挡。`posted` 是入账投影亮起来，AI 不能用嘴把它喊出来，也不能用它挡下一张。

### empty

还没有开始写。

| | |
| --- | --- |
| **老板看到什么** | 当前：还没有开始开单。按住说话。今日本可以是空的。 |
| **AI 能做什么** | 听第一句喊；写下客户和货，进入 `draft`。 |
| **AI 不能做什么** | 不盘货、不先问「今天开哪家」、不自动拿昨晚的待确认当当前。 |

### draft

已经有字，但还不能点头：可能客户没认清，可能还在连报、货还在写。

| | |
| --- | --- |
| **老板看到什么** | 当前已有称呼或货行。若两个王老板没说清，当前停在「哪个王老板？」货可以先看见，但不算认死。口播问一句人能答的。 |
| **AI 能做什么** | 继续往这张写；改口打在这张；问同名、问对不上的货。 |
| **AI 不能做什么** | 不许猜是哪家客户；不许静默套别人的常拿的货；不许这时把单定掉；不许跳去另一张。 |

「好了」按钮此时不可用或按下后口播说明还不行（没客户 / 客户没认清 / 没有货）。

### pending_confirm

这张已经认清人、至少有一行货，等老板点头。价未定也算到了这一态。

| | |
| --- | --- |
| **老板看到什么** | 当前整张草稿：谁、什么货、多少、价未定。状态字：「可以好了」。口播刚复述过。巨大「好了」可按。 |
| **AI 能做什么** | 继续听改口（量、去掉、再加），改完仍停在这一态并再复述；听「好了」或按确认。 |
| **AI 不能做什么** | 不自动确认；不因缺价追问打断；不因货够不够拒绝；不报价、不收款。 |

从 `draft` 到 `pending_confirm` 不需要老板多点一步：人一认清、货一落下，本子自己换成「可以好了」。

### confirmed

老板已经说「好了」。生意事实成立，这张合上。

| | |
| --- | --- |
| **老板看到什么** | 口播：单好了（有价未定则带上）。当前这张移入已确认。入账先显示「排队中」。嘴巴空出，等下一单。 |
| **AI 能做什么** | 等老板显式开下一张；用眼睛更新入账字。 |
| **AI 不能做什么** | **不能再喊着改这一张**；不能把确认撤回；不能把入账失败说成单没定；不能收款、扣库存、过账。 |

「好了」只走到这里。Confirm Gate 到此结束。

### posted

已确认之后，账上草稿看得见了。本子把「排队中」换成「已进草稿」。

| | |
| --- | --- |
| **老板看到什么** | 已确认行旁边：入账「已进草稿」。当前区不停留在这张（除非老板只是在看本）。 |
| **AI 能做什么** | 继续开下一张；保持这个字给眼睛看。 |
| **AI 不能做什么** | 不在口播里报入账；不拿「还没进草稿」挡「好了」；看不见时只标「看不见」，不装成成功，也不回滚确认。 |

若入账一直看不见，呈现停在 `confirmed` + 异常「入账看不见」，**没有第六态叫失败**。

### 状态对照（避免做成新内核）

| 本子呈现 | 老板话 | 现网事实（不改） |
| --- | --- | --- |
| empty | 还没开始 | 当前任务空，或尚无客户无行 |
| draft | 正在写 / 还要问 | 未确认；可能有同名阻断 |
| pending_confirm | 可以好了 | 未确认，且已能通过确认闸门 |
| confirmed | 定了 | `draft.status = confirmed`；turns 再改 → 拒绝 |
| posted | 进账了 | Read 投影 `posted`；不进闸门、不进口播 |

禁止为了这五态去改 Confirm Gate、新开 SpeechAct、或让 ERP 驱动状态机。

## 4. Voice First 入口

档口主操作是 **按住说**，不是打字，不是点加行。

```text
老板按住：「张老板苹果八十果二十箱」
        ↓
      语音（松开即一句）
        ↓
      理解（现有开单员，本页不重做）
        ↓
      生成草稿（写在当前这一张）
        ↓
      复述确认（一句口播 + 当前区亮出来）
```

这里的「复述确认」是 **给老板看我听成这样了**，还不是「好了」。真定点头仍要再说「好了」或按按钮。

### 4.1 屏幕上怎么配合

| 时刻 | 老板看见 |
| --- | --- |
| 按住 | 当前仍在；按钮变成「正在听」 |
| 松开 | 「正在写」 |
| 写完 | 一句大字口播；当前草稿更新 |

没有气泡、没有「用户 / 助手」两列、没有把每句原文留在本子上。上一句口播被下一句盖掉。本子留的是 **草稿事实**，不是聊天。

### 4.2 辅助，不是第二套入口

- 示例芯片（开张老板的单 / 苹果八十果二十箱 / 好了）只为 5 分钟试用降低第一句成本，不替代按住说话。
- 「好了」是大按钮，也可以喊出来。
- 「下一单」是小动作，确认之后才需要。
- 文本框仅在按住时作为档口没有麦时的等价入口，默认可收起。

### 4.3 不做的「智能」

不把页面做成对话 Agent：不建议「您是否还要加一行」、不弹出商品搜索、不自动跳到同名客户的旧单。听不清或认不准，只问一句人能答的。

## 5. 三个核心 Demo 场景

原型必须能当场走完下面三条。每条写清：老板做什么、本子怎么变、口播说什么。不要求 ERP 真站；入账可用「排队中 → 已进草稿 / 看不见」。

### 场景 A：正常开单

**目的：** 第一张单能喊出来、定下来、出现在今日本。

1. 开门。当前 empty。今天 0 张。
2. 按住：「张老板苹果八十果二十箱。」
3. 唯一张老板 → 当前进入 `draft` 随即 `pending_confirm`。看见：张老板，苹果 80 果 20 箱，价未定。
4. 口播：「张老板，苹果八十果二十箱，价未定。」
5. 按「好了」（或再说「好了」）。
6. 当前合上，进入已确认，入账「排队中」，稍后可变为「已进草稿」。今天 1 张。

失败则不算过：要先选客户再加行；口播编了单价；确认后当前还让改。

### 场景 B：修改未确认订单

**目的：** 改口打在当前这张，不必点表格。

1. 接场景 A 第 4 步，还没好了。当前 `pending_confirm`。
2. 按住：「刚才那个苹果不要二十箱，改三十箱。」
3. 当前行变成 30 箱，仍是 `pending_confirm`。
4. 口播：「张老板，苹果八十果三十箱，价未定。」
5. 「好了」→ 已确认的是 30 箱，不是 20。

失败则不算过：又加了一行 30 箱；改到别的单；没好了却当成已定；已确认之后仍让这一句改成功。

### 场景 C：两个同名客户歧义

**目的：** 两个王老板不许猜。

1. 当前 empty。按住：「王老板苹果六十件。」
2. 本子进入 `draft`：提示「哪个王老板？」列出能区分的档口（如 3 号档 / 7 号档）。货可先看见，不套任何一家常拿的货。
3. 口播只问哪一家，不复述成已经认死。
4. 按住：「3 号档。」
5. 认上 3 号档王老板，进入 `pending_confirm`，再复述。
6. 「好了」→ 已确认写的是这一家，不是另一家。

失败则不算过：静默选了最近一个王老板；没问就套了档案默认苹果；把两家开在同一张。

三条都走完后，今日本上应能看见对应的已确认行和入账字。允许再点「下一单」开第二张，证明不串页。

## 6. 产品验收标准

对象：一个 **没做过开发培训** 的农批老板（或扮演档口的人）。场合：打开这一页，旁边可以有人提醒「按住说话」，但不得替他点加行、不得打开 `?dev=1`。

**5 分钟内是否可以同时做到下面四件事：**

| # | 做到 | 现场看起来像 |
| --- | --- | --- |
| 1 | **创建第一张订单** | 喊出客户和货，当前区出现草稿 |
| 2 | **修改订单** | 未确认前改量或去掉，当前区跟着变 |
| 3 | **确认订单** | 说或按「好了」，这张出现在已确认 |
| 4 | **查看今日开单本** | 不翻页就能看见今天几张、待确认、已确认、入账字 |

四件都做到 → 原型过。卡住在「找不到该点哪」「以为要先登录进 ERP」「改口变成两行」「确认后还在当前里改」→ 不过。

不计入 5 分钟及格线（可有，但不挡过）：真机噪声零错、入账一定变成已进草稿、作废已确认单、收款、查历史。

补一条体验底线（与 5 分钟并列，当场能感觉到）：

- 全程只有一句业务口播，没有第二张嘴拼句子
- 没有库存、收款、报表入口抢第一屏
- 已确认后再喊改口，员工明确说这张已经定了

## 7. 老板坐一天，少了什么活

如果这个 AI 员工坐在档口旁边一天，老板最明显少掉的不是「系统更智能」，而是这几下手上的活：

**少抄一本。** 客报完不用再转身填表、不用再喊第二遍给伙计记。嘴里那句就是本上那行。

**少改错页。** 改口打在眼前这一张，不用在纸缝里找刚才那行，也不用两本对谁才是真的。

**少到收摊才发现漏了。** 空档扫一眼今日本：开了几张、哪张还没好了、哪张进账了没。不用翻微信聊天去对。

货还是自己看，钱还是自己收。少的是 **边卖边当书记员** 的那一层。这就是愿意让他坐一天的原因。

## 评审六问

1. **哪一层？** Demo / Workbench 呈现。不改冻结内核。
2. **改 LLM 权限？** 否。
3. **绕过 Policy / 改变 Confirm Gate？** 否。五态是呈现；「好了」仍走原闸门；`posted` 不进闸门。
4. **污染 Memory？** 否。本子不保存喊单原文。
5. **经 Event？** 确认留底仍走既有事件；入账字仍是 Read 投影。
6. **属于 Adapter 还是 Runtime？** 入账三字属已有 Adapter 投影；开单属已冻结 Runtime。今日开单本是工作台，不是新 Agent。

不确定则少做一列 ERP 字段，把按住说话和当前这一张留大。
