## 0. 怎么用这份表

1. 试班前：检查清单 §1 五项通过。  
2. 每个早市 / 每个营业日：填一张 **每日使用记录** + 当天的效率 / 信任 / 错误。  
3. **每一次失败**另开一条失败案例，不合并、不事后圆。  
4. 试班结束：用 §5 判断 **继续 V1.1** 还是 **调整产品流程**。

失败案例是行业语言资产，不是只拿来修 bug。能进 [DOMAIN.md](DOMAIN.md) / [LANGUAGE_BENCHMARK.md](LANGUAGE_BENCHMARK.md) 的口语，记原话。**禁止**把失败原话写进 Memory。

## 1. Pilot 目标

验证 AI 是否减少：

| 减少什么 | 现场怎么看 |
| --- | --- |
| **手写开单** | 纸本是否还在抄客户/货/量，还是只剩货和钱 |
| **重复确认** | 是否还在问「写了没 / 是 20 还是 30」 |
| **翻聊天找订单** | 空档和收摊是否还在翻微信，还是只看今日开单本 |

不验证：

| 不验证 | 为什么 |
| --- | --- |
| **AI 是否替代老板** | 货、价、放不放货仍是老板的 |
| **AI 是否无人值守** | Pilot 必须有人盯：换页、同名答档口、入账异常解释 |

成功时老板会说：**「这个东西确实帮我少记单。」**  
失败时老板会说：功能很多、听不懂、还是手写快。

## 3. 关键行为指标

数字服务「少记单」，不服务打分榜。时间用手机秒表即可，从开口到本子出现对应状态。

### 3.1 开单效率

| 指标 | 怎么量 | 当天 |
| --- | --- | --- |
| 第一次开单时间 | 开门后第一张：开口 → 当前区出现待确认草稿 | ________ |
| 平均开单时间 | 成功开单：开口报完 → 好了后已确认（不含等人装货） | ________ |
| 修改订单时间 | 未确认改口：开口 → 当前区数量/行变对 | ________ |

若改口经常变成两行或改错张，不要只记时间，必开失败案例。

### 3.2 信任指标

只记行为，不记满意度星星。

| 指标 | 是 / 否 / 次数 | 当天 |
| --- | --- | --- |
| 老板是否愿意继续喊下一单 | 第一张好了之后，是否自己开第二张，而不先抄纸 | ________ |
| 是否主动查看今日开单本 | 空档或收摊是否自己扫本子，不等观察人打开 | ________ |
| 是否回退手写 | 是否把同一张单又写回纸本/微信（开单那一层） | ________ |

回退手写 = 信任失败，即使成功开单数量看起来不少。

### 3.3 错误指标

每类计次。有一次就写失败案例。

| 类型 | 现场长什么样 | 当天次数 |
| --- | --- | --- |
| 客户识别错误 | 认错人、同名猜了、该问没问 | ________ |
| 商品理解错误 | 听成别的货、无档案却当已理解 SKU、改口变两行 | ________ |
| 串单 | 李老板的货写进别人或已确认页 | ________ |
| 状态不清 | 待确认/已确认/入账老板看不懂；以为好了=已收款 | ________ |

同名必须问、王记苹果必须挂起，算 **正确行为**，不要记进错误次数。观察人提醒「答档口」算人工介入，不算客户识别错误。

## 4. 必须记录失败案例

每一个失败单独一条。原话尽量原样。不要只修 bug，要把说法收成行业语言资产。

```text
案例编号：P-YYYYMMDD-__
日期 / 档口：
输入（老板说什么）：
AI 理解成什么（口播 + 当前区实际）：
最终正确结果（人认定该是什么）：
本子状态（当前 / 待确认 / 已确认 / 入账）：
人工是否介入：

原因（只勾一个主因）：
[ ] 数据不足     目录/档案/同名区分事实不够
[ ] 产品设计问题 换页、确认含义、今日本、Demo 口令映射让人用错
[ ] Runtime问题  Parser / 闸门 / 投递与设计不符（先记案例，改代码须另批且不破 Freeze）

可沉淀的口语（原词）：
下一步：只记资产 / 改呈现 / 改流程（不改闸门）
```

分类规矩：

| 主因 | 例如 | 不要做什么 |
| --- | --- | --- |
| 数据不足 | 现场有两个李老板、种子没有；新货名不在树上 | 不要猜客户、不要自动建 SKU |
| 产品设计问题 | 不知要「再开一单」；把复述当成好了；金脚本映射让人以为任意口语都行 | 不要为此改 Confirm Gate |
| Runtime 问题 | 同名没问；确认后仍改掉；入账失败却显示已进草稿 | 不要用新 Agent 绕过；先对照检查清单 |

语言资产去向：口语原词可补 DOMAIN / 语言评测金脚本。Memory 仍只从确认后结构化事件学习。

## 5. Pilot 结束判断

试满约定天数（建议至少 **3 个早市**，含 1 次高峰）后，只选一个方向。

### 继续 V1.1

同时满足：

1. 多数天：成功开单明显多于失败；回退手写为否或仅偶发。  
2. 老板原话接近「少记单 / 少翻聊天」，而不是「功能很多」。  
3. 错误以 **数据不足** 为主（缺客、缺货名），不是天天串单、状态不清。  
4. 检查清单五项仍通过。

V1.1 只做冻结 **外侧**：今日本更清楚、试班纪律、语言资产、可选关闭 Demo 口令映射做真实模式。**不**加收款、库存、第二员工，**不**改 Confirm Gate。

### 调整产品流程

出现任一条：

1. 成功开单少、人工介入几乎每张都要。  
2. 老板回退手写，或收摊仍只翻聊天。  
3. 失败主因是 **产品设计**（换页、确认含义、当前单看不清）或 **串单 / 状态不清** 反复发生。  
4. 为了现场顺滑想猜同名、确认后改单、让 ERP 挡「好了」。

先改旅程 / 工作台呈现 / 试班话术，再谈 V1.1。不扩功能。

### 成功标准（收口那一句）

老板感觉：

> 这个东西确实帮我少记单。

而不是：

> 这个 AI 功能很多。

## 评审六问

1. **哪一层？** Pilot 观察记录。不改内核。  
2. **改 LLM 权限？** 否。  
3. **改 Confirm Gate？** 否。  
4. **污染 Memory？** 否。失败原话不进 Memory。  
5. **经 Event？** 否。本文只记录。  
6. **Adapter 还是 Runtime？** 都不动。观察结果最多改 Demo / 工作台呈现或产品流程文档。
