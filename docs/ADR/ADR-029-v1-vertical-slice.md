# ADR-029

标题：V1 垂直切片复用已冻结流水线；P0 只让今日开单本跑完一分钟闭环

- 状态：proposed
- 日期：2026-08-17

## 背景

岗位规格、用户旅程、开单本原型已齐。内核已能开单、改未确认、确认写 Draft SO、Workbench 投影入账。若把「实现闭环」理解成再写一套 Runtime，会破坏 Freeze。

范围：[V1_SALES_CLERK_VERTICAL_SLICE.md](../V1_SALES_CLERK_VERTICAL_SLICE.md)。服从 [RUNTIME_FREEZE.md](../RUNTIME_FREEZE.md)。

## 问题

第一个可运行 Demo 做多大？是否重写开单流水线？

## 决策

1. 垂直切片 = **已有 Input → … → Outbox → Draft SO**，加上 Demo 上的今日开单本。不重构 Runtime，不新增 Agent，不改 Confirm Gate。
2. 复述当前草稿不是 Confirm。只能改当前未确认单。确认不是付款、不是发货。
3. **P0** 必须：开单、改量、好了、今日本变化（数量 / 当前 / 待确认 / 已确认 / 入账）。只动 Demo / Workbench 呈现与测试。
4. **P1** 下一阶段（张老板种子、下一单、点待确认、同名试用）。**P2** 暂不做（收款、库存、财务、确认后改单、ERP UI、第二员工）。
5. 5 分钟金脚本用现网唯一李老板；口号中的张老板不挡 P0。

## 原因

要证明的是「伙计能坐一分钟」，不是功能清单。内核已会写单；老板还看不见本子变了，闭环就不算产品化。

## 影响

- 好处：范围可砍；Freeze 可守。
- 限制：P0 不做同名必过、不做真机调优、不做收款。
