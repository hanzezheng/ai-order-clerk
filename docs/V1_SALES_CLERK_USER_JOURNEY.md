## 0. 老板雇的是什么

档口高峰时，客站在摊前连报，老板一边过秤一边喊。旧习惯是自己填表、叫伙计抄、或事后补进系统。抄漏、抄错、两本对不上，是真痛。

V1 这个员工做的是旧纸本伙计那一刀：**跟着喊、写得下、改得动、点头了就留底。** 货够不够、钱收了没有，仍是老板自己的眼睛和口袋。

他不是会计，不会在你说「好了」的时候问收款方式。他不是仓管，不会因为货看起来不够就拒单。他不是第二个老板，不会替你选客户、定价、决定这单做不做。

规格里的一天六步，在档口里就是下面这条路。本文按这条路把 **第一眼、每一句喊、每一眼本子** 写清楚。

```text
开门看本
  → 接单（反复）
  → 改口（未确认）
  → 好了（这张定了）
  → 空档看今日本
  → 收摊扫一遍
```

## 1. 开门

拉开卷帘、开灯、把货摆出来。钱箱和剩货是老板自己的事。系统这边只做一件准备：**把今日开单本摊开，等第一声喊。**

### 1.1 第一眼看到什么

不是菜单，不是仪表盘，不是 ERP 待办。

第一眼是一本 **今日开单本**：

| 老板看见 | 含义 |
| --- | --- |
| 标题「今日开单」 | 这是今天的本，不是历史账 |
| 今天 0 张 / N 张 | 开门常见是空本；重启后可能有昨晚没「好了」的草稿 |
| 当前：还没有开始开单 | 嘴巴还没对着任何一张 |
| 巨大的「按住说话」 | 客人一来就能喊，不用先填客户再加行 |
| 没有收款、库存、报表入口 | 那些不是这个伙计的桌子 |

空本是正常开张，不是错误。老板不需要先「创建今日班次」才能喊。

若昨晚有一张没好了的草稿，本子上会躺着，标成 **待确认**。AI 不会擅自拿它当今天第一单继续写——除非老板点它，把它变成当前这一张。

### 1.2 今日开单本如何呈现（开门时）

开门时本子很薄，结构已经和收摊时同一本（详见 §6）：

```text
今日开单                          待确认 1 · 已确认 0
────────────────────────────────
○  当前    还没有开始开单
────────────────────────────────
·  待确认  李老板  2行  价未定     ← 昨晚没好了，可点回来继续
```

不展示：金额合计、欠款、库存、ERP 单号、开发字段。

### 1.3 AI 员工如何准备工作状态

对老板来说，准备好 = **听得见、写得下、本子是今天的**。

| 准备 | 老板感受到的 | 不准备 |
| --- | --- | --- |
| 摊开今日本 | 今天的单都在这一页 | 不盘货、不对昨天欠款 |
| 待命听喊 | 按住就能说 | 不先问「今天开哪家」 |
| 记住没好了的草稿 | 本子上看得见 | 不自动接着昨晚那张写 |
| 一张嘴 | 之后每句回复都是同一句口播 | 不念 ERP、不念入账状态 |

开门完成的标志：老板看见本子，知道可以喊了。第一单从客人开口开始，不从点「新建销售订单」开始。

## 2. 接单（核心）

客人到摊前。老板不等系统问完，一整句甩出来。

### 2.1 真实场景

> **老板：** 张老板苹果八十果二十箱。

现场同时发生三件事：认人、认货、写下草稿。AI 必须跟着喊，不能把老板按进「先选客户 → 再选商品 → 再填数量」的表单。

**AI 当场做的：**

1. **认客户** — 档口里若只有一个张老板，直接认。若有两个，立刻问哪家档口，货先记下、先不套任何人的常拿的货。
2. **认货** — 「苹果」是品，「八十果」是规格，「二十箱」是量。能落到熟客常拿的那种苹果，就落，并在口播里点明；落不准就问，不猜、不替品。
3. **写下草稿** — 本张当前订单出现：张老板、苹果 80 果 20 箱、价未定。
4. **展示确认信息** — 口播复述 + 本子上当前这一张亮出来。这是给老板看「我听成这样了」，**还不是「好了」**。

口播只说业务，例如：

> **AI：** 张老板，苹果八十果二十箱，价未定。

不说单号、不说「已同步 ERP」、不说库存、不报价。

### 2.2 哪些自动完成 / 需要确认 / 必须询问

接单这一刀，分三种动作。老板只需要记住：**能写下的先写下，认不准的才问，定下来要你自己说好了。**

| 动作 | 谁做 | 张老板这句里的例子 |
| --- | --- | --- |
| **自动完成** | AI 立刻做，不问 | 听懂「张老板 / 苹果 / 八十果 / 二十箱」；生成当前草稿；缺价标成价未定；把草稿念给老板听 |
| **需要确认** | 必须老板点头（说「好了」或按确认） | 这张单作为生意事实成立、留底。**不是**每一行都打断问「对不对」 |
| **必须询问** | AI 不许猜，当场问 | 两个张老板是哪家；新客还没档口；「苹果」对这个客有好几种、档案也帮不上 |

再拆一层，避免把「展示草稿」和「确认留底」混在一起：

**自动完成（写下、复述）**

- 唯一匹配的客户，直接认上当前单
- 商品口语理解：品名 + 规格 + 数量进草稿
- 熟客档案里有「他一直拿的那种苹果」，自动套上，口播点明
- 没价：标价未定，**不打断问价**
- 连报下一品：继续写在同一张当前单，不等上一句问完

**需要老板确认（「好了」）**

- 这张单定了，可以留底
- 上一张定了之后，**显式开下一张**（见 §3）——AI 不因为听到新名字就擅自换单

**必须询问（认不准就停手乱猜）**

- 同名客户：哪个张老板（几号档）
- 新客：档口或能区分的事实，才能建档再往下开
- 货仍对不上：这句「苹果」对这家客有歧义，档案也没有默认
- 改口指代不清：本单有两行苹果，没说是哪一行

**既不问也不自动决定（留给老板做人）**

- 货够不够给
- 今天卖什么价、要不要按老价格
- 收不收款、现结还是挂账
- 这单做不做

### 2.3 另外两句，同一规则

> **老板：** 开李老板的单，苹果六十件，梨四十。

唯一李老板 → 自动认客、两行都写下、价未定、复述全单。老板再说「好了」才定。

> **老板：** 王老板，苹果六十。

若有两个王老板 → **必须问**「哪个王老板，几号档？」货先搁在手里，不套任何一家的常拿的货。老板答「3 号档」之后，再落到草稿上。

## 3. 连续接单

高峰不是开一张。是张老板还在装货，李老板已经在报下一车。产品必须让老板随时知道：**嘴巴正在写哪一页。**

### 3.1 真实上午

```text
7:12  「张老板苹果八十果二十箱。」     → 当前：张老板（待确认）
7:13  「好了。」                       → 张老板 已确认；当前空出
7:13  老板点「下一单」
7:14  「李老板梨六十件金边两箱。」     → 当前：李老板（待确认）
7:15  「金边改三箱。」                 → 仍是李老板这一张
7:16  「好了。」                       → 李老板 已确认
7:20  「开赵老板的单，苹果四十。」     → 当前：赵老板
```

### 3.2 四种单，老板怎么认

本子上只有四种状态。名字用档口话，不用系统词。

| 老板看见 | 是什么 | 嘴巴 | 手 |
| --- | --- | --- | --- |
| **当前订单** | 正在喊的这一张，有且只有一张 | 所有喊单、改口都打在这里 | 本子上这一行加亮 |
| **新订单** | 一张空白的当前单 | 还没喊，或刚点「下一单」 | 必须显式开；不因为听到新名字就自动开 |
| **待确认** | 写了还没说「好了」 | 只有它变成当前，才能继续喊 | 开门时可能看到昨晚留下的 |
| **已确认** | 已经点头留底的 | **不能再喊着改** | 仍留在今日本上，旁边看出入账没 |

「待确认」多数时候就是当前这一张。若老板没好了就去开下一张，上一张会留在本子上当待确认——V1 允许看见；要继续改，必须先点它变成当前。禁止靠一句「李老板」在好几张之间自动乱跳。

### 3.3 如何避免上下文混乱

档口乱，是因为人换得快，不是因为缺一个智能路由。V1 用三条死规定把笔按在一页上。

1. **一张嘴只对着当前这一张。** 口播复述的永远是当前草稿，不把已确认的张老板和正在开的李老板念成一单。
2. **换客先换页。** 张老板「好了」之后，下一句「李老板…」之前，要有明确的下一单（按钮或「开下一单」）。AI 不得把李老板的梨写进张老板那张已定单，也不得在未确认的张老板单上偷偷换成李老板。
3. **已确认是合上的页。** 对已确认单再喊改口，员工说：这张已经定了。要改，人上账或另开一张。不把今天所有「张老板」合成一个聊天。

老板不怕本子上有十二张。怕的是喊着李老板，写到张老板页上。所以 **当前是谁，必须在第一眼比口播还醒目。**

连续接单时本子长这样：

```text
今日开单                          待确认 1 · 已确认 2
────────────────────────────────
●  当前    赵老板  苹果40件  价未定
────────────────────────────────
✓  已确认  张老板  1行  价未定   入账：排队中
✓  已确认  李老板  2行  价未定   入账：已进草稿
```

## 4. 修改未确认订单

改口发生在货还没点头、单还没好了的时候。老板不会去点表格里的数量。

### 4.1 真实场景

> **老板：** 刚才那个苹果不要二十箱，改三十箱。

前提：当前这一张就是张老板，上面有一行苹果 20 箱，还没「好了」。

**AI 做的：**

1. **定位** — 「刚才那个苹果」= 当前单里正在写的那行苹果，不是今日本上任何一张叫苹果的历史单。
2. **修改** — 20 箱改为 30 箱。不是再加一行，不是新开一张。
3. **重新展示** — 口播：张老板，苹果八十果三十箱，价未定。本子上当前行跟着变。
4. **重新确认** — 改完仍是待确认。老板还要说一次「好了」，这张才定。改口本身不等于点头。

### 4.2 定位规则（老板能预期）

| 老板怎么喊 | 改哪 | 不改哪 |
| --- | --- | --- |
| 「那个苹果改三十」 | 当前单最近一行苹果 | 已确认的张老板单 |
| 「梨不要了」 | 当前单的梨 | 别人的梨 |
| 「再加十箱」 | 当前 focus 行累加 | 不新开一张 |
| 本单有两行苹果、没点名 | **必须问**哪一行 | 不许猜 |

定位失败时只问一句人能答的话，例如「哪一行苹果？」。不问库存、不问要不要重新计价。

### 4.3 改完之后

- 还没好了：继续喊或再说「好了」。
- 已经好了：员工拒绝当聊天改。口播清楚说 **这张已经定了**。今日本上那张保持已确认。老板要改量，另开一张或自己上账。

V1 不提供「把已确认单召回成当前再改」。那会让留底的事实和嘴里的话对不上。

## 5. 确认流程

老板说「好了」，或按确认。

### 5.1 确认代表什么

**确认 = 老板承认：这笔生意事实成立，可以留底。**

只这一句。展开成老板听得懂的边界：

| 确认是 | 确认不是 |
| --- | --- |
| 这张单定了 | 付款完成 |
| 客户、货、量（以及价未定）被记下 | 发货完成 |
| 公司账上会留一张草稿 | 财务完成、已过账、已核销 |
| 之后不能再喊着改这一张 | 货已经出了、库存已经扣了 |

价未定也可以「好了」。口播必须带上「价未定」，不能说成已经谈死。回头补价不是这个员工用嘴做的事。

### 5.2 确认之后老板看见什么

1. 口播：单好了；有价未定就说价未定。
2. 当前这一张从「待确认」变成「已确认」，合上。
3. 今日本多一条已确认。旁边用眼睛看出入账：排队中 / 已进草稿 / 暂时看不见。
4. 嘴巴空出来，等老板开下一张。

入账看得见、说不出。AI 不在嘴里报 ERP 单号，也不因为账还没进去就撤回「好了」。货放不放、钱收不收，仍是老板当场的事。

### 5.3 什么时候还不能「好了」

不是因为没付款。是因为 **人还没认清或单还是空的**：

- 两个张老板还没说是哪家
- 还没有客户
- 一行货都没有

缺价、货够不够、信用好不好，**不挡**「好了」。

## 6. 今日开单本（核心产品界面）

这是老板一天打开次数最多的一页。空档扫一眼、下一车来之前对一下、收摊再翻一遍。它替代的是纸本和微信里翻聊天，**不替代钱箱和库存。**

工作台就是这本。不是第二个 ERP，不是聊天记录。

### 6.1 一页上看见什么

```text
今日开单                 今天 12 张 · 待确认 1 · 已确认 11
────────────────────────────────────────────
● 当前   赵老板   1行  价未定              待确认
────────────────────────────────────────────
✓ 张老板  1行  价未定   已确认   入账：已进草稿
✓ 李老板  2行           已确认   入账：排队中
! 王老板  1行  价未定   已确认   入账：看不见
· 周老板  0行           待确认   客户还没认清
────────────────────────────────────────────
异常  入账看不见 1 · 还没好了 2
```

| 区块 | 老板用来干什么 | 不用来干什么 |
| --- | --- | --- |
| **今日订单数量** | 今天开了几张 | 不是营业额 |
| **待确认** | 还没点头的，别漏 | 不是欠款名单 |
| **已确认** | 已经留底的 | 不是已收款 |
| **ERP 入账状态** | 这张草稿进账了没 | 不是过账、不是总账；看不见就标看不见，不假装成功 |
| **异常任务** | 收摊前要盯的例外 | 不是财务红灯 |

### 6.2 每一张上有什么

谁、几行、价未定没有、当前还是已定、入账没。可选：确认时间。

没有：金额合计、SKU 编码、session id、口播原文、库存、收款标记。

入账三个字给老板：

| 看见 | 意思 |
| --- | --- |
| 排队中 | 定了，账还在写 |
| 已进草稿 | 公司账上有这张草稿了 |
| 看不见 | 暂时对不上，不代表单没定；人回头再看，不挡继续开下一张 |

### 6.3 异常任务（V1 就这几类）

异常是 **开单这一岗自己的漏**，不是财务预警。

| 异常 | 老板该做什么 | AI 不做什么 |
| --- | --- | --- |
| 还没好了（待确认留到空档/收摊） | 点回来继续喊，或自己决定不要了 | 不自动确认、不自动作废 |
| 客户还没认清 | 回答是哪家档口 | 不静默选一个王老板 |
| 入账看不见 | 知道这张留底可能还没进账 | 不改口播、不撤回「好了」、不自己重做财务 |

价未定是常态标签，**不算异常**。

### 6.4 本子上能点什么

- 点 **待确认** → 它变成当前，嘴巴对着它继续改、继续好了。
- 点 **下一单** → 新开一张空白当前。上一张如果没好了，留在待确认，不把两张揉在一起。
- 点已确认 → 只许看，不许喊着改。

自然语言仍只用来开当前这一张。本子不听长句、不当第二张嘴。

## 7. 收摊

货收回来、钱箱锁上、帘子拉下。主责是货和钱。开单员只把今天的本子递过来。

### 7.1 AI 能提供什么

同一本今日开单本，收摊时多两行人话摘要（写在本子上，不是新口令）：

- **今日订单汇总：** 今天 12 张，已确认 11，待确认 1；其中 4 张价未定。
- **未完成事项提醒：** 还有 1 张没好了；有 1 张入账看不见。

老板用这张清单对纸本、对记忆：「张老板那张写了没、进账了没」。

### 7.2 不能提供什么

| 不能 | 为什么 |
| --- | --- |
| 对账 | 对的是货和钱，这个员工手里没有钱，也不知道货是否出完 |
| 收款核销 | 确认开单不是已收款；核销是另一岗 |
| 财务判断 | 不说今天赚了多少、谁欠多少、该不该放货 |
| 盘点剩货 | 库存不是开单员 |
| 用嘴查「李老板今天拿了啥」 | 本子上自己看；不新增查账口令 |

收摊结束：老板合上今日本。AI 不关档、不锁钱箱、不生成日结凭证。明天开门，仍是同一类本子，日期换成明天。

## 8. V1 产品边界表

| 能力 | V1 是否支持 | 原因 |
| --- | --- | --- |
| 语音开单 | **支持** | 老板跟着喊就能写；这是雇这个伙计的理由 |
| 商品理解 | **支持** | 「苹果八十果」要听成规格+品，不能当一串乱码 |
| 客户识别 | **支持** | 认人才能写对单；同名必须问，不许猜 |
| 未确认修改 | **支持** | 档口改口比下单密；只改当前还没好了的那张 |
| Confirm（好了） | **支持** | 老板点头，生意事实成立并留底 |
| 今日开单本 | **支持** | 一天翻得最多的一页；开门、空档、收摊都看它 |
| 价未定可确认 | **支持** | 先开量、价回头再说，是农批常态 |
| 显式下一单 | **支持** | 连续接单不串页 |
| 入账可见（眼睛看） | **支持** | 知道草稿进没进账；不进口播 |
| 收款 | **不支持** | 确认不是付款；钱箱仍是老板的 |
| 库存 | **不支持** | 货够不够人看；缺货不挡「好了」 |
| 财务 | **不支持** | 不做核销、过账、营业额、欠款判断 |
| 确认后改单 | **不支持** | 定了就合页；再改会让留底和现场对不上 |
| 自动报价 | **不支持** | 行情日变；不静默套价、不替老板定价 |
| 第二员工 | **不支持** | 先让开单员每天坐得住；不顺便做收银/仓管/会计 |

## 9. 核心价值

**喊完就能留底：跟着我开、改得动、定了有本可对——货和钱我自己看着。**

这就是农批老板每天愿意让这个员工坐在档口的原因。不是因为系统功能多，是因为高峰时少抄一本、少漏一张，收摊还能看见今天开了哪些。

## 评审六问

1. **哪一层？** 用户旅程 / 今日开单本呈现。实现仍只允许 Input、Workbench 投影、Adapter 投影。
2. **改 LLM 权限？** 否。不新开查账口令，不让模型定价、选客、确认。
3. **绕过 Policy？** 否。「好了」仍只表示生意事实成立；入账状态不挡确认。
4. **污染 Memory？** 否。不从收摊对钱或催欠学习。
5. **经 Event？** 确认留底仍走既有确认事件；本子只展示。
6. **属于 Adapter 还是 Runtime？** 入账三个字属于已有投影；接单改口确认属于已冻结的开单员。今日本不是新 Agent。

不确定则回到这句话：嘴巴只写当前这一张，本子给人看，货和钱不进这个伙计手里。
