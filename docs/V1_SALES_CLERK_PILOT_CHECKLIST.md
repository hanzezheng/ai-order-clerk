PR40 已证明：老板可以完成 **一分钟开单闭环**。本文件回答下一问：

**真实老板用一天，这个员工可不可靠？** 不是还能做什么。

---

## 0. 结论

**可以进入有人盯着的档口 Pilot。还不能宣称已经可以无人值守坐一整天。**

| 可以带去摊前试 | 还不能当已经雇稳 |
| --- | --- |
| 唯一客户喊单、改未确认、好了、今日本变化 | 把 Demo 金脚本映射当成「什么口语都能听」 |
| 同名必须问、禁止猜（Runtime 已有；Pilot 要用 **王老板** 演练） | 种子里没有两个李老板；现场两个李老板须同一条规则 |
| 确认后改不了；ERP 失败不撤回「好了」，入账标异常 | 收款、库存、对账、确认后改单 |
| Outbox 确认事实不丢 | 真机噪声下零错、无监督全天 |

Pilot 成功看的是：少手写、少问「写了没」、少翻聊天找单。不看功能数量。

## 1. 真实使用前检查

摊前试班前，下列五项必须为 **通过**。查的是可靠性，不是新能力。

### 1.1 当前单是否永远明确

| | |
| --- | --- |
| **要看见** | 第一页最大一块写着当前是谁；口播复述的也是这一张。没有当前时写「还没有开始开单」。 |
| **禁止** | 两张单同时像当前；喊李老板却写到上一张已确认里。 |
| **怎么查** | 打开 `/`：空本时当前为空。金脚本开一张后，当前区是李老板。点「好了」后当前这张变已确认。再开一单，当前换成新空白页，上一张留在已确认。 |
| **现网** | Workbench `current_session_id` 只有一个。嘴巴只打当前 Session。已确认 turns → `409 task_completed`。 |
| **Pilot 记录** | 通过 / 失败：_______ |

### 1.2 Confirm 前是否可修改

| | |
| --- | --- |
| **要看见** | 待确认时改量，当前区立刻变成新数量；状态仍是待确认。改口本身不等于好了。 |
| **禁止** | 改完自动确认；改口变成两行。 |
| **怎么查** | 20 箱 →「刚才苹果改 30 箱」→ 当前仍待确认、数量 30。 |
| **现网** | 未确认合行 / 改量。P0 Demo 把金脚本「刚才苹果改 30 箱」映射为 Parser 已会的「苹果改 30 箱」。 |
| **Pilot 记录** | 通过 / 失败：_______ |

### 1.3 Confirm 后是否拒绝修改

| | |
| --- | --- |
| **要看见** | 「好了」后状态变 **已确认**。再喊改量，这张不动。界面说这张已经定了。 |
| **禁止** | 已确认被改掉；用聊天把留底改回去。 |
| **怎么查** | 好了之后再说「苹果改 40 箱」：本子仍是 30 箱已确认。 |
| **现网** | `409 task_completed`。Voice 壳会另开一张新任务，不写回旧单。 |
| **Pilot 记录** | 通过 / 失败：_______ |

### 1.4 今日开单本状态是否一致

| | |
| --- | --- |
| **要看见** | 今日张数、待确认、已确认、当前、入账字，同一时刻对得上。确认后：今日有内容的单 +1（或已确认 +1），当前这张从待确认进已确认，入账出现「排队中 / 已进草稿 / 看不见」。 |
| **禁止** | 已确认还停在待确认；入账字出现在未确认单上；假装进账成功。 |
| **怎么查** | 走完金脚本，数页眉数字，对当前区状态，对已确认行入账字。刷新页面（有库时）数字还在。 |
| **现网** | `GET /v1/workbench` 投影 `drafting \| confirmed` + `posting`。未确认 `posting` 为空。 |
| **Pilot 记录** | 通过 / 失败：_______ |

### 1.5 Outbox 是否可靠

| | |
| --- | --- |
| **要看见** | 「好了」之后，确认事实已经留下。ERP 当时写不进去，单仍是已确认，入账显示排队或看不见；稍后可变成已进草稿。 |
| **禁止** | 投递失败把确认撤回；重复确认写出两套互相打架的业务事实当两笔生意。 |
| **怎么查** | 开发侧：确认后 Outbox 该消费的 `order.confirmed` 能被 Adapter 处理；写失败后 `recover` 能补上 Draft SO。老板侧：只看「已确认」和入账字，不看队列。 |
| **现网** | Durable Outbox；写失败不改 `confirm_ok`；读失败 → `unavailable`。 |
| **Pilot 记录** | 通过 / 失败：_______ |

五项都通过，才允许约档口试班。任何一项失败：**不进入真实档口**，只修 Demo / 投影 / Adapter 外侧，不改闸门。

## 2. 异常场景

Pilot 不是再走一遍金脚本。下面五条必须在试班剧本里出现。通过标准：员工 **停手问人或标清楚**，不许默默编。

### 2.1 客户不明确

现场说法：「两个李老板。」现网种子是 **两个王老板**（3 号档 / 8 号档）。规则相同：称呼不是唯一键。

| | |
| --- | --- |
| **输入** | 「开王老板的单」（或现场两个同名李老板时喊「开李老板的单」） |
| **要求** | **必须询问**哪一家（档口）。货可以先搁，**禁止猜**最近一个，禁止套任何一家的常拿的货。 |
| **通过** | 当前停在「哪个王老板？」；确认闸门不过。老板答「3 号档」之后才认死。 |
| **失败** | 静默选了一家；口播已经按某家档案说红富士。 |
| **现网** | `customer_ambiguous`；`test_homonym_blocks_without_guessing`。 |
| **Pilot 记录** | 通过 / 失败：_______ |

不要为了 Demo 顺滑把同名改成自动选。那是不可靠。

### 2.2 商品不明确

用户举例：「苹果 20 箱。」

这里要分清 **有档案** 和 **没档案**，否则会把「按熟客默认」误判成「假装听懂」。

| 客 | 「苹果 20 箱」正确行为 | 假装理解（失败） |
| --- | --- | --- |
| **李老板**（档案默认红富士 80 果） | 落到默认货，口播 **必须点明按档案**；老板看得见规格 | 不说按档案，装成只有一种苹果 |
| **王记**（无苹果默认） | 行停在「苹果」，`product_ambiguous`，**不落到 SKU** | 随便拣一个 SKU / 替品 |

Pilot 两条都要做：

1. 李老板 + 苹果 → 允许默认，但必须点明。  
2. 消歧到王记 + 苹果 → 必须问或挂起，不能当已理解的 SKU。

缺价标价未定，**不是**商品不明确。价未定可确认。

**Pilot 记录：** 李老板默认 _______；王记挂起 _______

### 2.3 中途换客户

| | |
| --- | --- |
| **要求** | **不能串单。** 嘴巴只写当前这一张。换客先换页：上一张好了（或点待确认回来），再显式下一单。 |
| **通过** | 李老板已确认后，再开王老板，货只出现在新当前页；李老板那张数量不变。 |
| **失败** | 听到新名字就把梨写进李老板已确认单；或未确认的李老板单被改成王老板还带着李的货当同一张生意。 |
| **现网** | 不做 `start_order` 自动开新任务。已确认拒绝 turns。Pilot 操作纪律：换客按「好了 → 再开一单」。 |
| **Pilot 记录** | 通过 / 失败：_______ |

试班时若老板习惯连喊「下面李老板…」，旁边要有人提醒换页。这不是加智能路由的理由。

### 2.4 网络失败

| | |
| --- | --- |
| **要求** | **订单状态明确。** 这句没写上，就说没写上。不装成已经好了。 |
| **通过** | 断网或 turns 失败：当前草稿还是失败前那版；提示再说一遍；已确认的单不会因为刷新变回待确认。 |
| **失败** | 失败却显示已确认；或草稿消失。 |
| **现网** | Demo：`这句没接上，请再说一遍。` 有库时可重启恢复未完成 Session。 |
| **Pilot 记录** | 通过 / 失败：_______ |

### 2.5 ERP 写入失败

| | |
| --- | --- |
| **要求** | 老板知道：**已经确认，但入账异常。** 确认不是付款，也不是「ERP 一定写进去了」。 |
| **通过** | 「好了」后状态是已确认。入账是「排队中」或「看不见」，**不是**「已进草稿」。稍后恢复可以变成已进草稿。单不能改回去。 |
| **失败** | 写成未确认；或标成已进草稿其实没写上；或口播念 ERP 单号 / 报错当第二张嘴。 |
| **现网** | 写失败不改 `confirm_ok`；读失败 `unavailable`。P0 本子已有入账三字。 |
| **Pilot 记录** | 通过 / 失败：_______ |

## 3. Demo 与真实模式边界

| | **当前 Demo（金脚本）** | **未来真实模式** |
| --- | --- | --- |
| 目的 | 验证「旁边一分钟」体验 | 档口随便喊，走完整 Runtime |
| 入口 | `/` 今日开单本；可点芯片 | 同一页、同一 turns；**不再依赖芯片口令** |
| 金脚本映射 | `李老板苹果八十果二十箱` → `开李老板的单苹果二十箱`；`刚才苹果改30箱` → `苹果改30箱` | **关闭映射**。口语直接进 Parser |
| 客户 | 唯一李老板，避免同名挡体验 | 同名必须问（王老板 / 现场两个李老板） |
| 商品 | 李老板档案默认给出 80 果 | 无档案则挂起；有档案必须点明 |
| ERP | Fake Draft SO 即可 | 仍只写 Draft SO；失败只投影，不改闸门 |
| 证明了什么 | 本子、改口、好了、入账看得见 | 员工在噪声和同名里可不可靠 |
| 证明不了什么 | 「任意一句农批口语都听得懂」 | 收款、库存、全天无人看管 |

Pilot 纪律：

1. 给老板看体验，可以用 Demo 金脚本。  
2. 要下「能否试班」的结论，必须 **至少加跑 §2 异常**，其中同名、王记苹果、换页、入账失败 **不能只靠芯片映射**。  
3. 不得把 Demo 映射写进 Parser，也不得为了 Pilot 顺滑改 Confirm Gate。

## 4. Pilot 成功标准

不是功能数量，不是评测分数。

一个老板连续使用一天（或一个早市），是否减少了：

| 旧痛 | Pilot 中应减少 | 怎么判断 |
| --- | --- | --- |
| **手写记录** | 少抄一本、少填一行 | 试班结束问：今天还要不要另写纸本？纸本只剩货和钱，还是连开单也在写？ |
| **重复确认** | 少问伙计「写了没 / 是 20 还是 30」 | 改口后当前区就是新数量；好了后不用再对一遍表 |
| **查聊天记录找订单** | 少翻微信对「李老板那张」 | 空档和收摊只看今日本：谁、几行、待确认还是已确认、入账没 |

货够不够、钱收了没有，Pilot **不要求**减少——那不是这个员工的岗。

一天结束，三问都偏「是，少了」→ Pilot 成功。  
仍在手写开单、仍在翻聊天找单 → Pilot 失败，回来修呈现或试班纪律，不扩 ERP、不加第二员工。

## 5. 是否可以进入真实档口测试

**可以进入：有监督的档口 Pilot。**

条件（缺一则先不要去摊）：

1. §1 五项检查通过。  
2. §2 五条异常在剧本里有人会演、会记通过/失败。  
3. 老板知道：确认 ≠ 收款；入账看不见 ≠ 单没定。  
4. 旁边有人：换客提醒「再开一单」；同名提醒答档口。  
5. ERP 只当 Draft 留底；不 submit、不扣库存、不收款。

**不可以进入的形态：**

- 把芯片金脚本当成已经听懂全部档口话  
- 无人值守、没人解释「待确认 / 已确认 / 看不见」  
- 指望它盘货、收钱、对账  
- 为了现场顺滑去改 Parser 或 Confirm Gate

一句话：P0 证明他能坐一分钟。Pilot 检查他忙的时候会不会瞎写。瞎写的口子 Runtime 已经闸住；试班要做的是 **把闸门用在真实嘴里，而不是再做一个更聪明的员工。**

## 评审六问

1. **哪一层？** Pilot 检查清单。不改冻结内核。  
2. **改 LLM 权限？** 否。  
3. **改 Confirm Gate？** 否。异常场景只验证已有闸门。  
4. **污染 Memory？** 否。  
5. **经 Event？** Outbox 可靠性已是现网契约；失败不回滚确认。  
6. **Adapter 还是 Runtime？** 入账异常属 Adapter 投影；问同名、挂起歧义货属已冻结 Runtime。
