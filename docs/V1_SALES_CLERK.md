本文把第一个商业员工收成可雇规格：**农批 AI 销售开单员 V1**。

DESIGN §14 的「V1」是 Sprint 6A 的 **POC 开单壳**（文本模拟麦、当时不接 ERP）。本文的 V1 是 Runtime 收口之后的 **商业员工版本**：同一岗、同一 Runtime，把「喊单进账」做成老板一天用得上的产品。

---

## 0. 结论

1. V1 雇的是 **开单伙计**，不是档口经理、会计、仓管、收银。
2. 老板一天六步里，AI **主责**只有中间三步：**接单 → 改未确认单 → 确认**。开门、收摊、货、钱仍是老板自己的。
3. **查看今日订单** V1 必须能用眼睛完成（今日开单本 + 入账状态），不能用嘴当查账口令。
4. V1 做的是把现网能力 **产品化**，不是再做一个内核。实现只走 Freeze 外侧：Input / Workbench 投影 / Adapter 投影。
5. V1 **明确不做**收款、库存、submit、确认后改单、第二员工、ERP 指挥 `confirm_gate`。

```text
开门（人工）
  → 接单（AI 主责，反复）
  → 修改（AI 主责，仅未确认）
  → 确认（AI 主责；账上 Draft SO）
  → 查看今日订单（AI 给本，老板用眼睛）
  → 收摊（人工；AI 只提供今日本）
```

## 1. 这个员工是谁

| | V1 |
| --- | --- |
| 岗位名 | 农批 AI 销售开单员 |
| 版本 | V1（第一个可雇商业版本） |
| 老板买的 | 不用填表，喊完一单，账上留底 |
| 不是 | 档口经理、会计、仓管、收银、CRM、ERP 前端 |
| Session | 仍是一张 `SalesSession`；一单结束不得当聊天继续改 |
| 企业账 | ERPNext 存 Draft Sales Order；AI 不在 ERP 里做决定 |

老板对伙计的完整期待本来是「开单、改单、收钱、看货、催欠」。V1 **只雇开单这一刀**。其余继续人工，或留给以后另一个员工。

## 2. 老板一天真实工作流程

农批档口不是 ERP 菜单。高峰时客站在摊前连报，老板一边过秤一边喊，改口比下单还密。空档才有空看「今天开了几张」。收摊才对货、对钱。

下面按真实顺序写六步。每步写：老板在干什么、现场长什么样、和系统的交接点。

### 2.1 开门

档口拉开卷帘、开灯、把昨晚剩货摆出来。老板扫一眼货够不够卖、钱箱里有没有零钱、熟客会不会一开门就来拿。旧习惯是翻纸本或打开旧开单软件，看有没有没写完的单。

这一步的业务动作是 **准备开张**，不是下第一单。

交接：打开工作台，看到「今日开单本」——可能是空的，也可能有昨天没确认完、重启后还在的草稿。不在这一步盘库存、不对昨天欠款。

### 2.2 接单

客到摊前或电话打进来。老板开口通常是一整串，不等系统问完：

> 「开李老板的单，苹果六十件，梨四十，金边再加两箱。」

可能先报客再报货，也可能熟客只报货。市场里多个「王老板」时，必须问是哪家档口，不能默默选最近一个。新客要当场问清楚再往下开。

这一步会在高峰里 **反复发生**，一张接一张。上一张「好了」之后，必须显式开下一张，不能把新客的货开进旧单。

交接：语音或文本进现有 turns；系统维护本张草稿（客户、行、价未定）；口播只有一句 `reply_text`。

### 2.3 修改

货还没点头、单还没「好了」时，改口是常态：

> 「不对，苹果改八十。」
> 「梨不要了。」
> 「那个再加十件。」

老板不会停下来点表格。改的是 **正在喊的这一张未确认单**。

客已经把货拉走、单已经确认之后，现场改法是另开一张、或老板自己上 ERP / 纸本改。那不是开单员用嘴继续聊。

交接：未确认单上合行、改量、去掉；确认后 turns 返回 409，不再当聊天改。

### 2.4 确认

老板说「好了」或按确认。现场含义是：**这张单定了，可以留底**。不一定已经收款，不一定货已出完，不一定单价已谈死。

农批常见：先开量、价回头按今日行情再填。V1 允许缺价确认，口播必须说「价未定」，不得把 TBD 说成已成交。

交接：Confirm Gate 通过 → `order.confirmed` → Outbox → Draft Sales Order。确认在 Runtime 完成。ERP 失败不撤回「好了」。入账状态事后用眼睛看。

### 2.5 查看今日订单

中午空档、下一车来之前、或收摊前，老板要知道：

- 今天开了几张
- 都是谁
- 哪张还价未定
- 哪张进公司账了、哪张还在排队、哪张暂时看不见

旧习惯是翻纸本、翻微信、问伙计「李老板那张写了没」。V1 用 **今日开单本** 替代翻本，不替代问账。

老板 **看**，不 **问**。「李老板今天拿了啥」不能当成查账口令。`query_draft` 只念 **当前这张** Runtime 草稿。

### 2.6 收摊

收货、点剩、锁钱箱、对今天谁拿了货谁还没给钱、拉帘。这一步的主责是 **货和钱**，不是再开一张单。

开单员能提供的只是今日本：开了哪些、进草稿了没。对不上的现金、挂账、剩货，老板自己处理。V1 不在收摊时做日结凭证、收款核销、库存盘点。

## 3. 当前 AI 能承担哪些步骤

「能承担」= 现网 Runtime **已经具备**这条行为，不是下个 Sprint 才发明。V1 要把它变成老板用得上的产品，见 §5。

| 步骤 | AI 现在能做的 | 证据（现网） | 不能当成已经产品化的缺口 |
| --- | --- | --- | --- |
| **开门** | 工作台列出当天任务与当前单；重启后未完成草稿还在 | Workbench 当日索引；Postgres 可重启 | 列表还不是「今日开单本」：客户、行数、价未定、入账没，老板一眼不够 |
| **接单** | **主责**。连报多品、不打断追问；同名必须问档口；熟客可套档案默认；新客冷启动建档 | 多 SpeechAct、`expect_more`、同名闸门、Memory `product_default`、冷启动 | 档口噪声下真机语音是否稳，仍属 Input，不属内核 |
| **修改** | **主责（仅未确认）**。合行 / 改量 / 去掉 | Policy + OrderService；确认后 409 | 老板可能以为确认后还能喊着改——产品必须把「这张已定」说清楚 |
| **确认** | **主责**。缺价可确认；确认写 Draft SO；失败不回滚确认 | `price_tbd` + Confirm Gate；Outbox → Write Adapter | 入账结果不能用嘴说；开发态之外要能看见 `pending \| posted \| unavailable` |
| **查看今日订单** | **辅助看见**。任务卡片可挂 `posting`；本单 `query_draft` 念 Runtime 草稿 | Read Adapter 投影；Workbench `posting` | 投影在，产品壳不足；禁止升级成查账对话 |
| **收摊** | **只提供今日本**。与「查看今日订单」同一份索引 | 同上 | 不承担对钱、对货、锁档 |

一句话：AI 已经能当开单伙计的手和嘴（接、改、定）；眼睛看今日本的数据已在装配层，还没当成老板的本。货和钱 AI 现在不能碰，V1 也不碰。

承担原则：

- **能喊着完成、且闸门已存在** → 开单员主责。
- **能看见、不能用嘴问账** → 工作台投影。
- **要货或钱才能闭环** → 继续人工。

## 4. 哪些步骤必须继续人工

不是「以后再做的功能清单」，是 **V1 岗位边界**：这些动作若交给 AI，就会变成仓管、收银或第二员工。

| 步骤 | 必须人工 | 为什么不能交给这个员工 |
| --- | --- | --- |
| **开门** | 开档、摆货、盘剩、开钱箱、决定今天卖什么 | 库存与现金不进 `SalesSession`；ERP 不得指挥开张 |
| **接单** | 判断货够不够给、当场议价、拒绝这单 | 库存 / 信用不得进 `confirm_gate`；AI 不替老板做生意决定 |
| **修改** | 已确认单的改量、改客、作废后重开以外的账务改单 | Session 一单结束；确认后改单会破坏闸门与 Outbox 契约 |
| **确认** | 决定是否真的把货放行；价未定之后回头填成交价 | 成交价补录会改已确认事实；属另一张任务或人工上 ERP |
| **查看今日订单** | 用眼睛对，不用嘴问「谁欠多少」；认账仍由老板 | 新查账 SpeechAct 会改 Parser；Read 进嘴巴会改 Policy notice |
| **收摊** | 收款、找零、挂账核销、点剩货、锁档、对发票 | 支付 / 财务 / 库存是别的岗；现在不启动第二 Employee |

现场仍由老板负责、系统不得代劳的硬规则：

1. **货在不在摊上** — 人看。缺货不挡「好了」。
2. **钱收了没有** — 人收。确认开单 ≠ 已收款。
3. **两个王老板是哪家** — 人回答档口事实；AI 只许问，不许猜。
4. **已确认的单** — 人改账或另开一张；AI 拒绝当聊天继续改。
5. **ERP 单过不过账、submit 不 submit** — 人在企业系统里做；Adapter 只写草稿。

## 5. V1 必须产品化的能力

「必须产品化」= 老板不看 `?dev=1`、不读日志，也能把一天六步里属于开单员的部分做完。现网多数行为已经存在，V1 **不是再写一套 Runtime**，是把外侧做成这个岗位。

实现必须落在 Freeze **允许的扩展点**：Input Adapter、Workbench 投影、Read/Write Adapter 投影。禁止改冻结层来「补产品」。

| # | 能力 | 老板一天里用在哪 | 现网基础 | V1 产品形态 | 落在哪一层 |
| --- | --- | --- | --- | --- | --- |
| 1 | **喊着开单** | 接单 | turns + Parser + Policy | 档口默认走语音壳；文本仍等价；一张嘴只念 `reply_text` | Input |
| 2 | **未确认改口** | 修改 | 合行 / 改量 / 去掉 | 改完立刻出现在本单；不诱导去点表单加行 | 已冻结内核（只展示） |
| 3 | **同名消歧** | 接单 | 必须问档口 | 口播问句老板听得懂；禁止静默选 | 已冻结内核（只展示） |
| 4 | **价未定可确认** | 确认 | `price_tbd` | 「好了」后明确说价未定；今日本标记该张缺价 | 已冻结内核 + 投影 |
| 5 | **显式下一单** | 接单（反复） | `POST /v1/workbench/tasks` | 上一张定了之后，老板能开下一张给另一个客；禁止自动把话路由进旧单 | Workbench |
| 6 | **今日开单本** | 开门 / 查看今日 / 收摊 | 当日任务索引 | 一眼：谁、几行、价未定没有、当前还是已定 | Workbench 投影 |
| 7 | **入账可见** | 确认之后 / 查看今日 / 收摊 | `pending \| posted \| unavailable` | 每张已定单旁边能看见进账没；失败显示不可见，不假装成功 | Read 投影 |
| 8 | **确认留底** | 确认 | Outbox → Draft SO | 老板理解「好了 = 这张定了、账上会留草稿」；不要求看见 ERP 单号 | Write Adapter（已有） |

产品验收（老板动作，不是单测）：

1. 开门后看见今日开单本（空也行）。
2. 开口开一张缺价单，改一次口，说「好了」。
3. 听见价未定；本子上出现这张单。
4. 看见入账 `posted` 或 `pending` / `unavailable`。
5. 再开第二张给另一个客户。
6. 收摊前能从头到尾扫一遍今天开过的单。

不要求：嘴上念 ERP 单号、真机 ASR 在所有噪声下零错、作废已过账单、收款、查历史成交。

可选、不纳入 V1 必做：消费已有 `order.cancelled` 去取消 ERP 草稿（Write Adapter 新 consumer）。那是日结可见的增强，不是开单岗能不能雇的门槛。

## 6. V1 明确不做的能力

| 不做 | 若做会破坏什么 |
| --- | --- |
| 第二个 Employee（收款员 / 采购 / 仓管） | 未验证的第一岗被当成平台；必新开 Session 与闸门 |
| 库存够不够、缺货挡确认 | ERP / 库存驱动 `confirm_gate` |
| 收款、找零、挂账核销、发票、总账 | 支付 / 财务进 SalesSession；确认开单被当成已收款 |
| submit / 过账 Sales Order | Adapter 越权；企业过账变成 AI 副作用 |
| 「李老板今天拿了啥 / 账上还有单吗」口令 | 新 SpeechAct；Read 进嘴巴 |
| 确认后补价、改行、换客 | Session 已结束；Outbox 已发出确认事实 |
| 静默选同名客户、静默套价、自动替品 | 已冻结的 Resolver / Memory 闸门 |
| 表单加行当主操作、ERP 页面当工作台 | 产品变成 ERP 前端，不是开单伙计 |
| Policy notice 念 ERP 单号 / posting | 口播语义绕过 Policy；ERP 进入决策层 |
| 改 Parser / Confirm Gate / OrderService / Memory | 修改 Runtime Freeze |
| LangGraph / 多 Agent 总管 / 抽象员工平台 | Freeze 明确禁止 |
| 登录、多租户、信用额度引擎 | 超出第一岗；财务驱动开单 |

V1 也 **不修改** [RUNTIME_FREEZE.md](RUNTIME_FREEZE.md)。产品缺口用外侧补，不重新谈判内核。

## 8. 与已完成阶段的关系

| 已完成 | V1 拿来做什么 | V1 不拿来做什么 |
| --- | --- | --- |
| AI Runtime | 接单 / 改口 / 确认的裁决 | 不改冻结层「补产品」 |
| Voice Adapter | 喊着开单的默认壳 | 不改 `reply_text` 语义 |
| ERPNext Write / Read | 确认留底；入账可见 | 不让 ERP 选客、选 SKU、挡确认 |

## 9. 后续实现约束（本文不写代码）

落地 V1 产品化时，每个 PR 仍须声明只改哪一层。允许动的只有：

```text
Input Adapter（真机语音可用性）
Workbench / Demo 投影（今日开单本、入账可见、下一单）
装配层挂已有 posting（不进 BusinessContext）
```

禁止动的与 Freeze 相同：Parser、ProductUnderstanding、Resolver、Policy、Confirm Gate、OrderService、Memory、`SalesSession` 一单、`BusinessContext` 字段、Runtime Freeze 正文。

路径仍是：

```text
老板 → Input Adapter → Turn Intake → Parser → Understanding
  → Resolver → Policy → Domain Service → Event → Outbox
  → Memory | ERPNext Write Adapter → ERPNext
装配层 Domain Query → ERPNext Read Adapter → 领域事实投影
```

## 评审六问

1. **哪一层？** 产品规格。实现只允许 Input / Workbench 投影 / Adapter 投影。
2. **改 LLM 权限？** 否。不新开 SpeechAct，不让 LLM 选客、选 SKU、定价、确认。
3. **绕过 Policy？** 否。确认仍只走 Confirm Gate；`posting` 不进 `BusinessContext`。
4. **污染 Memory？** 否。不从收摊对账或催欠对话学习。
5. **经 Event？** 确认事实仍经 Outbox 写 ERP；今日看见走 Read 投影。
6. **属于 Adapter 还是 Runtime？** 留底与入账可见属 Adapter；接单改口确认属已冻结的 Sales Runtime。今日开单本属 Workbench 投影，不是新 Agent。

不确定则保持开单员 V1 边界，不启动第二员工，不改 Freeze。
