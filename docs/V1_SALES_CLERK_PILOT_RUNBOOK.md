## 0. 结论

第一个 Pilot 是一次 **有人盯着的早市执行**，不是上线发布。

```text
前一天：切片 + 设备 + 网络 + 负责人 + 检查清单五项
第一天：开门 → 第一单 → 高峰 → 收摊
        只观察老板是否主动用
陪跑：提醒换页、答档口、解释状态；不代选客、不代点好了
必须停：串单、猜同名、确认后还改、用库存/钱挡确认、老板说停
收摊四问 → 观察表 + 反馈模板
结束：继续扩大 / 继续观察 / 暂停
```

核心看：老板会不会自己喊下一单、高峰还用不用、收摊看不看本、明天还用不用。

## 1. Pilot 前准备

缺一样不要去摊。准备是人做的，不开发账号系统、不实施 ERP。

### 1.1 企业事实准备

按 [数据边界](V1_SALES_CLERK_PILOT_DATA_BOUNDARY.md) / [访问](V1_SALES_CLERK_PILOT_DATA_ACCESS.md) / [接入](V1_SALES_CLERK_PILOT_ONBOARDING.md)：

| 要 | 不要 |
| --- | --- |
| 客户切片（≥ 5，含 1 组同名；id / name / alias / 消歧） | 库存 |
| 商品切片（≥ 5 叶 SKU；id / name / spec / alias） | 欠款、财务 |
| 经 Adapter 或等价人工投影进 Catalog | 全量历史 SO、客户画像 |

抽查：喊唯一熟客能落到人；喊「王老板」会问哪家；主货能落到可确认叶。

真实第一单 **关闭 Demo 口令映射**，或只用切片里的真称呼。金脚本只给陪跑人热身。

### 1.2 账号

V1 **不要求**老板登录、不要求多租户。

| 谁 | 「账号」指什么 |
| --- | --- |
| 老板 | 没有。打开今日本就能喊 |
| 陪跑人 | 知道打开哪一页、哪套切片；ERP 若接了，凭证只在 Adapter，不给老板填 |

不要现场给老板开 CRM 账号、不要教 ERP 菜单。

### 1.3 设备

| 项 | 要求 |
| --- | --- |
| 屏幕 | 手机竖屏，一臂距离能看清当前区 |
| 入口 | 浏览器打开今日开单本（`/`），不要 `?dev=1` |
| 麦 | 按住说话需麦克风权限；文本等价可用，高峰优先语音 |
| 备用 | 纸本仍在桌上。停 AI 时老板能立刻手写，不堵摊 |

### 1.4 网络

| 项 | 要求 |
| --- | --- |
| 档口 | 手机流量或 Wi‑Fi 能打开页面、提交 turns |
| ERP | 可选。断了则入账显示看不见；**单仍可「好了」**，不改闸门 |
| 失败 | 读取失败不能猜客/货。页面打不开 → 停 AI，改手写 |

### 1.5 负责人

| 角色 | 人 | 职责 |
| --- | --- | --- |
| **档口老板** | ________ | 喊单、点头「好了」、货和钱仍自己管 |
| **陪跑人** | ________ | 本手册执行、记账、提醒、决定停不停 AI |
| **事实补录** | 可与陪跑人同一人 | 缺客/缺 SKU 补来源再投影，不在摊前开发 |

当天必须有陪跑人在场。无人值守不开始。

检查清单 §1 五项通过后，才能按本文跑第一天。

## 2. 第一天流程

只记行为和习惯，不记功能点。

**日期：** ________　**档口：** ________　**陪跑人：** ________

### 2.1 开门

时间：________

| 看 | 记 |
| --- | --- |
| 今日本是否空本，「还没有开始开单」 | 是 / 否 |
| 老板是否自己打开页面（不等陪跑人塞手机） | 主动 / 要提醒 |
| 有没有先去翻微信/纸本当第一动作 | 是 / 否 |

空本是正常开张。不要让老板先「创建班次」或先填客户。

### 2.2 第一单

时间：________　原话：________

走接入规定的路径：切片里已有的客和货 → 当前区出现草稿 → 未确认可改 → 「好了」→ 本子变已确认。

| 看 | 记 |
| --- | --- |
| 是否老板开口，而不是陪跑人示范代喊 | 是 / 否 |
| 好了之后老板有没有看一眼今日本 | 是 / 否 |
| 是否主动喊第二张（不等「你再开一单」） | 主动 / 要提醒 / 回退手写 |

第一单失败：按询问/挂起补事实，**不要**为了交差代选客或代点好了。记失败模板。

### 2.3 高峰期

时段：________　大约几张：________

| 看 | 记 |
| --- | --- |
| 老板是否仍对着页面喊 | 主动用 / 半用 / 回纸本 |
| 换客是否还要人提醒「再开一单」 | 每次 / 偶尔 / 自己会 |
| 同名是否自己答档口 | 是 / 要提醒 / 出现过猜 |
| 是否出现必须停 AI（§3.2） | 是 / 否；原因：____ |

高峰仍手写 = 习惯没形成，不要用「功能还不够」解释。先记流程/信任问题。

### 2.4 收摊

时间：________

| 看 | 记 |
| --- | --- |
| 老板是否自己扫今日本 | 主动 / 要打开给他看 / 只翻聊天 |
| 纸本是否还在抄开单那一层 | 是 / 否 |
| 入账看不见时是否还认「单已定」 | 清楚 / 不清楚 |

然后做 §4 四问。填观察表用量 + 反馈模板。

### 2.5 当天习惯观察（收口）

**老板是否主动使用？**

| 主动 | 不主动 |
| --- | --- |
| 开门自己开页面 | 等陪跑人把手机递过来 |
| 第一张好了自己喊下一张 | 每张都要「再开一单」 |
| 高峰还对着本喊 | 一忙就只写纸 |
| 收摊自己扫本 | 只翻微信找单 |

当天结论：主动 / 半主动 / 不主动。这是结束判断的输入，不是功能评分。

## 3. 陪跑规则

陪跑人是 **安全员 + 记录员**，不是代班开单员。

### 3.1 人工什么时候介入

| 可以介入 | 怎么做 | 不要做 |
| --- | --- | --- |
| 换客仍往旧单上喊 | 提醒「再开一单」 | 不替他点、不把话路由进旧单 |
| 同名系统在问 | 提醒答档口/电话 | 不替他选是哪一家 |
| 状态看不懂 | 解释待确认 / 已确认 / 入账看不见 | 不说「看不见就是没开成」 |
| 缺客、缺 SKU | 让系统问/挂起；记下补投影 | 不编一个客户、不新建 SKU |
| 网络/页面挂了 | 宣布改手写 | 不猜着开 |

介入记一次「人工接管」。高峰时优先保摊，提醒一句即可，不要讲解产品。

### 3.2 什么情况必须停止 AI

出现任一条，陪跑人 **当场说停**，改回纸本。不停着猜。

1. **串单**：李老板的货写进别人或已确认页，且当前区已经乱。
2. **猜同名**：系统或人默默选了最近一个王老板。
3. **确认后还改**：已「好了」的单仍被 turns 改掉。
4. **想用库存/欠款/收款挡「好了」**，或现场开始收钱当确认。
5. **页面打不开 / 一直超时**，还在口头编结果。
6. **老板明确说停**，或不信任并改回手写保生意。
7. 检查清单闸门被破坏：无当前单却在写、复述被当成已经确认。

停止之后：记失败案例（主因 Runtime 或产品流程）。**不要**当场改 Confirm Gate、不要上新 Agent 救场。生意用纸本跑完。恢复试用须重新过 §1 准备。

停 AI ≠ Pilot 失败一天。停是保护档口。当天仍做四问。连续两天必须停 → 倾向 **暂停**。

## 4. 每日复盘

收摊后口头问老板，陪跑人记 **原话**。不要改成问卷量表。

1. **今天 AI 帮你少做了什么？**
2. **哪一步最麻烦？**
3. **哪一次你不信任 AI？为什么？**
4. **明天还会用吗？**

| 问 | 听什么 | 对上反馈类 |
| --- | --- | --- |
| 少做了什么 | 少抄、少问写了没、少翻聊天 = 习惯 | — |
| 最麻烦 | 换页、按住说话、看不清当前 | 流程 |
| 不信任 | 不敢好了、写错人/货、状态乱 | 信任 / 理解 |
| 明天还用 | 核心标准 | 结束判断 |

第 3 问若有具体一单，当天补一条失败模板。第 4 问与反馈闭环同一句，不要问两遍不同的「满不满意」。

## 5. Pilot 结束判断

建议至少 **3 个早市**（含 1 次高峰）后再选。第一天只出「当天习惯」，不宣布可雇。

不要根据功能数量判断。根据老板习惯判断。

只选一个输出：

### 继续扩大

多数天：

- 老板 **主动使用**（自己喊下一单、高峰还对着本、收摊看本）。
- 第 4 问「明天还会用」。
- 失败以缺客缺货为主，能补事实闭环；没有靠猜才换来「还用」。
- 检查清单五项仍通过。

扩大 = 同一档口更多熟客进切片、陪跑人少提醒换页。仍有人盯。仍不加收款库存。对应接入的扩大、反馈闭环里可进入 V1.1 的那扇门（V1.1 本身仍是冻结外侧，不在本手册里开发）。

### 继续观察

- 「明天还用」只有一天，或高峰没见到。
- 半主动：会用，但每张都要人提醒。
- 失败还分不清是数据还是流程，样本不够。

继续按本手册跑，不扩功能、不换第二个档口。

### 暂停

- 多数天不主动、第 4 问不愿再用，或回退手写。
- 连续必须停 AI。
- 串单/猜同名/确认后改单反复。
- 现场要求上 CRM、库存、支付才能继续。

停扩大、停宣传可雇。回去补切片或改旅程/工作台。不改 Confirm Gate。

```text
习惯（主动用 + 明天还用）
  → 继续扩大
习惯未稳、样本不够
  → 继续观察
不信任 / 必须停 / 要加库存支付
  → 暂停
```

## 评审六问

1. **哪一层？** Pilot 执行手册（人怎么跑第一档口）。不改内核。
2. **改 LLM 权限？** 否。
3. **改 Confirm Gate？** 否。必须停时改手写，不放宽闸门。
4. **污染 Memory？** 否。复盘原话进观察/反馈表。
5. **经 Event？** 否。只有老板说「好了」才确认。
6. **Adapter 还是 Runtime？** 都不改。事实仍经投影；执行是陪跑纪律。
